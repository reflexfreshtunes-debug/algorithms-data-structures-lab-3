# Работа №3 — задания №1 и №2

Учебные реализации на C++14 без STL-контейнеров и готовых алгоритмов сортировки.

Для подготовки к объяснению начните с `EXPLANATIONS.md`: там оба задания,
шаблоны, итераторы и дерево разобраны короткими и простыми фразами.

## Содержимое

- `common/binary_search_tree.hpp` — общий шаблонный класс двоичного дерева поиска;
- `task_01` — BST, три итератора и интерпретатор команд;
- `task_02` — хронологическая сортировка сообщений через BST.

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

## Задание №1

Запуск готового сценария из корня репозитория:

```bash
./build/task_01 task_01/commands.txt
```

Без аргумента команды читаются из консоли. Интерпретатор использует целые ключи и значения, но само дерево является шаблонным и может работать с другими типами.

Поддерживаются команды:

```text
upsert <key> <value>
find <key>
remove <key>
TraversePref
TraverseInf
TraversePost
```

Правило порядка передаётся в конструктор дерева отдельным объектом-компаратором. Итераторы заранее запоминают порядок узлов и возвращают ключ, изменяемое значение и глубину. Пока существует итератор, структуру дерева изменять нельзя.

### Сложность

Пусть `h` — высота дерева, `n` — число узлов.

- добавление, поиск и удаление: `O(h)`; в среднем `O(log n)`, в худшем `O(n)`;
- построение и полный проход итератора: `O(n)` времени и `O(n)` памяти;
- копирование дерева: `O(n)`.

## Задание №2

Программа принимает ровно один аргумент — путь к файлу сообщений — и перезаписывает этот файл в хронологическом порядке:

```bash
./build/task_02 task_02/messages.txt
```

Формат строки:

```text
dd.MM.yyyy hh:mm:ssUsername: message
```

Проверяются календарная дата, время, имя пользователя и структура строки. Для одинакового времени сохраняется исходный порядок записей. Все записи сначала успешно загружаются в память, и только после этого файл открывается для перезаписи.

### Как работает сортировка

Дата, время и исходный номер строки образуют ключ BST. Более ранняя дата попадает левее более поздней. Инфиксный обход дерева посещает ключи по возрастанию, поэтому его результат сразу записывается в файл.

- вставка одной записи: `O(h)`;
- загрузка всех записей: в среднем `O(n log n)`, в худшем `O(n^2)` для уже упорядоченного входа;
- инфиксный обход и запись: `O(n)`;
- память: `O(n)`.

## Управление памятью и ошибки

Дерево, итераторы, сообщения и динамические текстовые буферы имеют конструктор копирования, оператор присваивания и деструктор. Потерянные ключи, неверные команды, некорректные даты и ошибки открытия файлов обрабатываются исключениями; произвольного завершения программы из вспомогательных функций нет.
